## Current behavior

- GET /books returns 200 and a JSON array, initially empty.
- GET /books/{id} returns 200 and the requested book, or 404 with an empty body if it does not exist.
- PUT /books/{id} replaces title, author, and price for an existing book and returns 200. Missing books return 404. Incomplete or invalid input returns 400 without changing stored data.
- DELETE /books/{id} returns 204 with no body when deleted, or 404 if the book is missing. Other books remain unchanged.
- POST /books accepts title, author, and price. It returns 201 and the saved book with a generated ID.
- Blank or missing title/author, missing or negative price, and malformed JSON return 400 without changing stored books.
- Zero price is allowed. Books with the same title receive different IDs.
- Books are stored in memory and disappear when the application restarts.

Prerequisites: JDK 21 or newer compatible with Spring Boot 3.5, and Maven 3.6.3+.

From this directory:

```sh
mvn test
mvn clean verify
mvn spring-boot:run
curl -i http://localhost:8080/books
```

The automated test starts the full Spring application context and uses MockMvc to check HTTP routing, status, content type, validation, saved books, and the empty response. It does not open a network port.

## Test coverage

Run `mvn clean verify` to run tests, build the application, generate coverage reports, and enforce at least 70% overall production-code line coverage. `mvn test` runs tests but does not run the coverage report or threshold check.

Open `target/site/jacoco/index.html` after verification to inspect coverage. On October 21, 2026, all 26 tests passed with 94.74% line coverage (36/38 lines) and 100% branch coverage (10/10 branches). No custom coverage exclusions are configured. JaCoCo filters some generated bytecode automatically.

The uncovered lines are in the application main method. MockMvc tests start a Spring context without calling that entry point. Coverage measures execution, so assertions and behavior checks remain essential.
